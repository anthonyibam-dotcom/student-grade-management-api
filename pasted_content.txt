### 2. Database Models & Pydantic Schemas

1. **Student Model**: `id` (UUID or Autoincrement PK), `first_name`, `last_name`, `email` (unique, validated), `enrollment_date`, `created_at`.
2. **Course Model**: `id`, `code` (e.g., "CS101", unique), `title`, `credits` (1-5), `description`.
3. **Grade Model**: `id`, `student_id` (FK), `course_id` (FK), `score` (float 0.0 - 100.0), `letter_grade` (auto-computed: A, B, C, D, F), `semester` (e.g., "Fall 2026").

### 3. API Endpoints (RESTful CRUD & Analytics)

Implement API versioning under `/api/v1`:

- **Students (`/api/v1/students`)**:
  - `POST /` - Create student (validate email format)
  - `GET /` - List students (with pagination query params `limit` and `offset`, search by name)
  - `GET /{id}` - Get student by ID (include enrolled courses and GPA summary)
  - `PUT /{id}` - Update student info
  - `DELETE /{id}` - Delete student (cascade handle grades)

- **Courses (`/api/v1/courses`)**:
  - Full CRUD operations

- **Grades (`/api/v1/grades`)**:
  - `POST /` - Submit score for student & course
  - `GET /` - List grades (filter by `student_id` or `course_id`)
  - `PUT /{id}` - Update score (recalculates letter grade)
  - `DELETE /{id}` - Remove grade record

- **Analytics (`/api/v1/analytics`)**:
  - `GET /students/{id}/gpa` - Calculate cumulative GPA/weighted average for a specific student.
  - `GET /courses/{id}/stats` - Get mean score, max score, min score, and passing rate for a course.
